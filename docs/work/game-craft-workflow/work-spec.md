# Game craft workflow

**Purpose:** Transfer the judgment developed through Ash & Echo into Vasir's normal game workflow, so agents find and repair weak art and feedback without the creator supplying every correction.
**User journey:** Ask Vasir to build or improve a game → it establishes that game's intended experience → the appropriate specialists implement coherent art and response → it inspects real play, repairs observed weaknesses and delivers a playable result with honest remaining limits.
**Engineering system unlock:** Existing skill routing carries the critique/repair behavior into fresh contexts; the recorded conversation is no longer required input.
**vFinal:** Reusable, normally discoverable game-direction, art, juice and orchestration guidance that applies across genres, cameras, input devices and engines, with practical forward checks on contrasting non-platformer games.
**Entrypoint:** Ordinary game creation or broad polish requests through `game__orchestrating-playable-build`; narrow requests still route directly to their owner.

## North Star

The agent derives what the player attends to, does, changes and tries next. It selects a fitting visual and motion language, implements the actual experience, observes ordinary play and consequential variations, and repairs the largest evidenced gap. A reader of the resulting skills can make a calm board game or a forceful embodied game without importing fog, jumps, an avatar, portrait layout or a required effects count.

Success means the guidance changes implementation and critique decisions in a fresh game. The next action is another game-specific improvement or an accepted stopping point. Skill installation, procedural compliance and model enthusiasm alone do not establish a good game.

## Observable contracts

- **C-001 — Brief first:** Explicit genre, style, camera, platform, pacing and user scope survive skill routing. Defaults fill missing decisions; they do not replace stated ones.
- **C-002 — Domain judgment:** Art owns relational composition and material grammar; juice owns state/consequence response and recovery; orchestration owns evidence-led iteration. Siblings link to these owners instead of copying their rules.
- **C-003 — Relevant feedback:** A game without an avatar, real-time motion, physical impact or a spatial world does not acquire those systems merely to satisfy polish instructions. Quiet, rigid, pixel, textual and abstract styles remain valid.
- **C-004 — Observed repair:** A broad quality pass inspects the actual relevant action/choice sequence, includes its aftermath and next action, and repairs a named experienced failure. A peak screenshot or passing functional suite cannot substitute for a motion claim.
- **C-005 — Useful completion:** Existing authorization supports autonomous implementation and review. The agent reports the observed result and material limitations without inventing human taste acceptance or repeatedly asking permission to do approved repairs.
- **C-006 — Transfer evidence:** Fresh bounded non-platformer tasks exercise the revised workflow; the report separates actual builds/play observations from static routing probes and prediction. Ash & Echo runtime remains unchanged.

Complete. The five revised skill owners and their conditional references are authored and cataloged; repository metadata/registry checks pass. These are transfer checks, not a workflow-uplift benchmark or universal quality certification.

## Decisions

- Keep the current skill owners; no new mega-skill. Conditional examples carry genre-specific detail.
- The reference bar is relational craft and responsive, legible play, not the gothic palette, fog or raven.
- Cross-game behavior checks are warranted because copying platformer-specific fixes would visibly fail the user's explicit requirement. Keep the cases and reports bounded; do not add a scoring framework or public benchmark result.
