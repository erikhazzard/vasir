# Post-submission play and media

Generation has ended before any evaluator opens the game. The source tree remains frozen. Build and static-host packaging follows the authored entrypoint or package scripts, with an explicit deployment base where the authored build tool supports it. A build failure stays a failure; the evaluator does not repair game code.

The observer uses a 390 × 844 mobile browser viewport with native touch events. Read the visible instructions, start through the authored control, attempt ordinary movement/jumping and progression, then use the authored recovery or restart if encountered. Observe the game before inspecting implementation for a diagnosis. Keyboard input can investigate declared keyboard support but does not establish mobile play. No teleporting, game-state injection, altered timing, invincibility or completion scripting.

First retain an ordinary first-look session to identify the visible controls and attempt play. Remote observer/tool latency can leave long pauses between actions; these are operator pauses, not evidence that a character ignored held input. After this bounded familiarization, record one separate continuous demonstration from a fresh browser context with a scheduled sequence of actual touch inputs: start, jump/hold, steer in both directions, continue through imperfect movement, and attempt applicable recovery. Adapt coordinates to the authored controls, without reading or controlling game state. No completion bot or successful-take selection. Apply this procedure to every available submission.

The public clip comes from that demonstration at normal time: remove setup before one second preceding its first input, then retain the next 90 seconds or the remaining capture, whichever is shorter. This includes missed inputs, failed jumps, pauses and recovery. Both original untrimmed silent sessions and timed input traces remain retained. The poster comes from five seconds into the clip (or its midpoint for shorter clips); judge frames are evenly sampled. First-look media and diagnostic sessions are labeled separately for reviewers and cannot be replaced with only successful moments.

This observer-procedure correction was recorded after Moonward's first-look session showed long tool-round-trip pauses, before any game quality judging and before other submissions were captured. The original first-look recording is retained. It changes no contestant prompt, model run, source, deadline or game behavior.

`capture-session.mjs` hashes the packaged runtime before and after play, records the submitted artifact hash, and checks actual local browser response bodies against the same file manifest. `prepare-media.mjs` pins the original capture, derived clip, poster and sampled frames to that receipt. A retained media file is not proof of its own provenance without this binding. Historical Ash & Echo footage uses its separate revision-23 source and asset identity records.

Each judge receives anonymous runtime/media and neutral observed facts in an independent session, without model identity, condition, cost, other judgments or this conversation. Judge output is source-bound by the harness after review. Publication retains failures, missing evidence and disagreement. Emulated touch and sampled visual review do not establish physical phone comfort, unobserved audio quality or human enjoyment.
