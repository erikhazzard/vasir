# Creation runtime audit

The bounded audit covered `run-storytelling-creation.js`, `storytelling-creation-runtime.js`, their shared runtime paths, and the generation/runtime tests. No frozen generation source or existing generation artifact was changed. This is a local audit note, not a public benchmark result.

## Final-answer retention on a failing CLI exit

The shared `agent-runtime.js` parser obtains the last Codex `agent_message`, but rejects every nonzero process exit without attaching that message to the error. `storytelling-agent-runtime.js` retains the stream SHA-256 and observed tool metadata, not the raw failed stream. `isCreationOperationalRetry` can subsequently classify a timeout in stderr as operational.

A mocked process emitted a final `agent_message`, a `turn.completed` event, stderr `timeout waiting for cleanup`, and exit status 1. The resulting error did not contain the final answer, while `isCreationOperationalRetry({outputText: null, error})` returned true. This demonstrates a late-teardown failure path that could otherwise reroll an already returned answer. It does not establish that any live creator answer was lost.

The generation runtime remains frozen. There is no automatic retry loop. The operator must inspect failed generation attempts and retry only unmistakable failures before answer generation, such as a model-manager startup timeout. Teardown failures and ambiguous failures must remain unresolved and visible; an absent archived answer alone does not prove that no answer was emitted. Never retry an output-policy rejection or select a replacement for an accepted story.

At the audit checkpoint, 16 accepted creator responses had distinct session IDs, the expected isolation flags, no supplied skill or file-reading calls in plain responses, and frozen staged references for observed skill reads. The one failed Terra xhigh skill response reported a model-manager startup timeout after approximately 15 seconds, with no observed model or reference activity. That observed startup diagnostic is distinct from the reproduced teardown scenario.

At 03:38 UTC on September 8, all 138 Codex creator slots were complete, with 138 distinct fresh session identifiers and matching saved answer hashes. The single model-manager startup failure was manually reviewed and retried once, using the same frozen prompt, configuration, treatment, and trial slot. Its initial error remains in the attempt history; no accepted story was replaced. All 138 receipts also passed the creation-specific flags and supplied-context checks. The 60 Claude slots were still pending the provider's explicitly reported 11:50 p.m. America/New_York session-limit reset; this checkpoint is not a claim of a completed benchmark.

## Judge guard and implementation freeze

The new judge-only adapter observes the native CLI stream in addition to reusing the creation runtime. If the CLI emits a final judge message and then fails, the failed attempt retains that exact text and its SHA-256 and is marked nonretryable. The invocation remains failed; its ratings are not silently accepted or replaced. A mocked regression test covers the final-message/nonzero-exit case.

Before the first judge invocation, `creation-judging.json` freezes the complete bytes and SHA-256 hashes of the judging implementation and its direct shared runtime/configuration dependencies in `implementationSnapshot`. Resuming execution requires identical current implementation bytes. Archive validation separately verifies the frozen source hashes, original generation run hash, context files, original judge outputs, receipt isolation, attempt history, and all four-seat arithmetic.

Harmless CLI `item.type=error` notices can be present without tool use. The judge receipt guard allows only those explicit notices with no command, path, agent IDs, or status; observed tool invocations remain disqualifying. Host skill discovery, skill search, project instructions, shell tools, apps, and multiple-agent tools are explicitly disabled for judges. These controls document observable supplied context and tool access; hidden provider instructions and pretrained knowledge remain outside verification.
