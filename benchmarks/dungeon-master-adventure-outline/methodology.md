# Dungeon Master adventure outline, edition v1

This is a frozen, repeated comparison of explicitly invoking the Dungeon Master skill. The exact primary task is `create an outline for TTRPG adventure`, with six independent matched repetitions. Five independently authored transfer prompts have two repetitions each. Each pair contains one plain and one skill-assisted outline: sixteen pairs and thirty-two planned writer sessions. Every contestant requests `gpt-6-astra` with `ultra` reasoning. Generation concurrency is four and each CLI invocation has a twenty-minute operational timeout, without an imposed answer word cap or output-token ceiling. These are fresh CLI processes; Ultra may use internal collaboration, so CLI counts are not a verified count of underlying model agents.

Before scored generation, freeze every case, repetition count, rating instruction, configuration, random scheduling seed, skill file and runtime dependency. The frozen skill contains all files of the specified skill directory, including the root and linked references. The skill is not edited or selected using these results. Infrastructure probes are separately retained and excluded from scoring. A new treatment or corpus requires a new declared run.

The user task is byte-identical across conditions. The treatment alone receives an explicit Dungeon Master invocation and the frozen skill root as a provider instruction. It must read every byte of `references/adventure-design.md` through a bounded read helper; other references remain selectively accessible. Receipt verification matches the successful helper output to the frozen reference bytes, rather than accepting a claimed read or a filename. A valid response that skips a required read is retained with its adherence status and is not regenerated to improve adherence or quality.

Each CLI process begins in a fresh temporary workspace. The native command permission profile denies filesystem-root access and reopens only minimal runtime paths, the fresh workspace, and the Node binary directory. Commands have no network access; browser, web search, apps and plugins are disabled. Each installed skill is explicitly disabled by its exact path in the CLI skill configuration; the generic host-discovery feature flag alone proved insufficient in the preserved preflight. Project instructions are disabled. The native permission profile prevents model tools reading global skill directories; no nested host sandbox is used. The host process retains its existing authentication context without copying or logging credential values; inherited session/proxy/hook environment variables are excluded. A baseline sentinel probe must confirm forbidden reads fail and no installed skill catalog is supplied. A treatment probe must confirm instruction delivery and actual frozen-reference access before scored calls begin.

The run retains every exact final answer, prompt, SHA-256 identity, word and Unicode-character count, original usage fields, parsed invocation receipt, timestamps, reference-read evidence and technical attempt. Complete provider stdout/stderr streams are retained privately with hashes and restricted permissions; public projections must never expose those streams, session identifiers, absolute runtime paths, credentials or internal instructions. Exact final answers and frozen skill content are public evidence. The legacy adapter's normalized usage remains distinguishable from retained provider usage and raw streams. Model/effort identity is described as an exact CLI request unless provider output independently confirms it.

One technical retry is allowed only for missing-answer transport, connection, timeout or transient server failures with unchanged inputs. Completed weak content, refusals, task noncompletion, missing skill reads and unfavorable scores never justify retries. Authentication, quota, policy-filter and filesystem/configuration failures are not automatically retried. Retain each failure and keep its planned cell in coverage. Resume reuses completed valid output byte-for-byte and acquires the run lock before reading checkpoints. Only one writer mutates run.json; judging writes a separate judges.json checkpoint.

Two independent fresh Astra Ultra judge sessions receive each intact pair. The exact task, frozen independent rubric, and opaque full candidate answers are supplied; condition, generator identity, invocation instructions and other judgments are withheld. Candidate order is counterbalanced across the two seats. Each judge scores both candidates on the six equal 0–5 dimensions with textual evidence before recording a direct A/B/tie preference, confidence, and separate fundamental-repair/task-noncompletion flags. These are assessments within a paired context, not individually presented absolute ratings. No human or different-provider calibration is present; shared-model and recognizable-style bias remain explicit limitations.

The six dimensions and all neutral interpretation rules are fixed in `judge-rubric.md` and `benchmark.json`. Scores are the dimension mean divided by five and multiplied by one hundred, then averaged across the two judges. Missing/invalid judgments are null, not zero. Both seats are required for a complete pair. No overall score caps or forced canonical adventure template apply. Preserve original dimension evidence, disagreements, direct pair preferences and flags even when preference differs from rating totals. Any explicit experimental-identifier removal must be logged; substantive wording and organization are preserved.

Report the six primary pair differences separately from the ten transfer pairs, and display all cases/repetitions. Transfer cases receive equal case weights; a pooled descriptive sixteen-pair mean must be labeled as repetition-weighted and never replace primary results. Show per-dimension scores, paired differences, win/tie/loss and flags alongside length, latency and available cost/usage. Additional judge ratings are not independent writing samples. Six curated prompts do not support universal claims about adventure design. This measures the practical skill invocation, including additional context and tool behavior, without controlling away resulting answer length.

The publication uses a separately pinned source and subsection under Writing. It does not alter Storytelling's selected source or join Dungeon Master scores to Overall. Exact source hashes, missingness, frozen skill material, prompts, full answers, original evidence and operational limits remain inspectable. The guarded publisher and source-exact browser checks must establish live delivery before the work is called published.
