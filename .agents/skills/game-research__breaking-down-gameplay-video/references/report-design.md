# Evidence-Led Report Design

The report is both a research artifact and a compelling editorial explanation. The evidence graph constrains it; the report does not retroactively shape the graph.

## Thesis selection

Choose the opening only after reconciliation and model selection. Rank candidate theses by:

1. explanatory power across multiple observed systems;
2. importance to the run or clone;
3. evidence strength;
4. surprise or counterintuition;
5. ability to connect visible experience to hidden machinery.

The ending, death, victory, or loudest event is eligible—not mandatory.

## Default modular architecture

Include modules only when evidence supports them, but a full reconstruction normally contains:

1. **Hero finding:** outcome plus the highest-leverage reconstruction insight.
2. **What the source can and cannot reveal:** manifest, timing, observability, coverage, method, chip legend.
3. **Run/session chronology:** acts, phases, decisions, transitions, terminal state.
4. **The core loop:** action → feedback → resource/state change → next decision.
5. **The machine:** clocks, state machines, formulas, entities, AI, spawning, economy, progression.
6. **The hidden spreadsheet:** constants, ranges, curves, schedules, operation order, candidate models.
7. **Genre-specific autopsy:** activated adapter findings.
8. **Feel grammar:** synchronized control/animation/camera/VFX/audio/UI timelines.
9. **Pacing and pressure:** power/threat/resource/decision curves scoped to the source.
10. **World and encounter logic:** topology, spatial incentives, camera, navigation.
11. **Player model:** information state, choices, execution, habits, alternatives, coaching.
12. **Baseline-clone blueprint:** preservation contract, reference implementations, fixture coverage.
13. **Corrections and conflicts:** what changed and why.
14. **Coverage boundary and unknowns:** opportunity counts, blind spots, observational equivalence, unidentifiable internals.
15. **Design verdict:** load-bearing systems, engagement logic, portable lessons, and what a “better” version could change after the baseline is faithful.

## Evidence presentation

- Cite source ID and PTS interval in every evidence caption.
- Use clips/film strips for order and duration; use stills/crops for exact visible states.
- Include context before/after the focal event when causality or reaction matters.
- Place conflicts and alternatives at the point of attribution, not only in an appendix.
- Make `n=1` and scope visible wherever the claim reappears.
- Every table/chart cell that influences an argument resolves to claim/model IDs in machine data.

## Reader-facing epistemic language

Use direct verbs only at the correct layer:

- `OBSERVED`: “HP falls from 52 to 40.”
- `MEASURED`: “The visible attack cycle is 1.92–2.00 s across eight valid repetitions.”
- `STATED`: “The menu states +10 damage.”
- `MODELED`: “The trace is best explained by a two-state chase/attack cycle.”
- `DESIGN-READ`: “This likely turns reload timing into a positioning decision.”
- `PLAYER-MODEL`: “The movement is consistent with creating room before reading.”
- `REFERENCE-IMPLEMENTATION`: “The baseline clone uses additive +10 because equivalent alternatives are not separable here.”
- `OPEN`: “The footage cannot distinguish time-triggered from kill-triggered spawn.”

Never write the last seven as if they were the first.

## Prose bar

- Lead with consequences; use numbers and event sequences to carry the argument.
- Explain the denominator before the result.
- Use one strong metaphor only when it compresses a real system relationship.
- Prefer exact scope over vague hedge words.
- Second person is appropriate when analyzing the user’s play.
- Preserve counterarguments and alternative models in the main text when they change the conclusion.
- Do not praise complexity. Explain what each system does to decisions and experience.

## Tables

Required high-value tables include as applicable:

- source/observability table;
- event chronology;
- constants and ranges;
- formula/model comparison;
- entity/state-machine inventory;
- economy/source-sink table;
- upgrade/progression eras;
- AI opportunity/cycle table;
- player decision table;
- unknown/reference-implementation table;
- clone preservation contract and fixture matrix.

Every rate table names clock, window, numerator, denominator, and aggregation.

## Charts

Choose adapter-valid axes; universal-looking axes are not a virtue if they measure the wrong construct.

Useful patterns:

- stepped power/resource curves with event rails below the plot;
- threat/density/HP/speed curves with uncertainty bands;
- state timelines and event rasters;
- formula candidate predictions against observed points;
- attack/feedback micro-timelines;
- world paths only with a validated coordinate model;
- zone/band charts for scoped run pressure;
- Sankey/flow diagrams only when source/sink quantities are reconciled;
- state-machine diagrams with observed versus reference-implementation edges distinguished.

Rules:

- draw uncertainty and alternate models;
- label off-scale values with bounded arrows, not infinity;
- use plain reader-facing time labels;
- keep text off the data surface when a callout rail/grid is clearer;
- distinguish observed, modeled, and reference-implementation marks visually;
- render-check every chart at desktop and narrow width; clipping, label collisions, unreadable contrast, and misleading interpolation are defects.

## Visual structure

Default to a self-contained evidence-first web report:

- strong typography and restrained surfaces;
- one readable prose measure;
- figures large enough to inspect source details;
- horizontal overflow for dense film strips/tables;
- relative assets and no dependency on a particular cloud destination;
- accessible captions and text equivalents for essential visual findings.

Style is configurable. Analytical semantics are not.

## Cross-surface generation rule

Generate report facts from canonical claims/models/spec IDs. Do not manually retype values into hero text, tables, charts, and spec. The presentation adversary must compare rendered claims against canonical records and flag drift.

## Corrections

Give material corrections their own visible section:

- original read;
- new evidence;
- corrected read;
- downstream report/spec changes;
- whether the correction reveals an instrument or reasoning failure.

Corrections increase credibility only when they remain visible and propagated.
